# Decisions

Why Studio is the way it is. **(user)** marks a decision the user made,
**(proposal)** one waiting for the user's word.

| # | Decision | Why |
|---|----------|-----|
| S001 | Studio is a native Rust application: no HTML, no JavaScript, no webview **(user, M0)** | The user's requirement; wowlua's decision T300 already planned "a native Rust IDE" that links the libraries in its own process. wowlua's roadmap M15 described a browser front-end with a desktop shell; it changes to this. |
| S002 | Desktop first, on Windows, macOS and Linux; a browser build stays possible later: everything is drawn on `wgpu`, and dependencies must build for `wasm32-unknown-unknown` **(user, M0)** | WoW's players and addon authors use all three; wowlua's libraries below Studio already build for the browser (T301). |
| S003 | The UI is egui (eframe) on `wgpu`; Studio's heavy views (the editor, trees, tables, the flame graph) are its own widgets painted with egui **(user, M0)** | Proven for large native tools that also run on the web; egui-wgpu 0.37 uses `wgpu` 30, as `wowlua-render` does, so the game's screen and Studio share one device. |
| S004 | wowlua is a git dependency pinned to a release tag; working on both repositories at once, a path patch in `.cargo/config.toml` (kept out of git) points to a local checkout **(user, M0)** | CI and releases build what the tag says; local work changes both without publishing. |
| S005 | Performance comes first: Studio redraws only when something changed, draws only what is visible, and keeps checks, tests and the game off the UI thread; frame times are measured from M0 on **(user, M0)** | It has to feel snappy. |
| S006 | Studio has its own semantic version; a release names the wowlua version built in. Each minor version closes a milestone of the roadmap; releases within a milestone bump PATCH **(user, M0)** | Studio and wowlua release on their own schedules. |
| S007 | Studio's spec (this roadmap and these decisions) lives in this repository; wowlua's roadmap M15 points to it **(user, M0)** | Studio's plans change with its design, not with the compiler's. |
| S008 | On macOS Studio follows the platform: its window buttons, the system menu bar and `cmd`; on Windows and Linux the title bar is as designed **(user, M1)** | The design draws Windows' window buttons and `ctrl` everywhere. |
| S009 | The first release opens packages from folders, with local git; GitHub (pull requests, Actions) and the online workspace with no folder are a later milestone (M12) **(user, M0)** | The online workspace needs a host per workspace in wowlua and an in-process command runner. |
| S010 | A dependencies view for wowlua's registry (search, add, update, outdated) is designed and built for the first release (M10) **(user, M0)** | wowlua 0.13 added the registry; the design has no view for it. |
| S011 | The profiler opens the in-game recordings of wowlua's dev window too, in the first release (M7) **(user, M0)** | wowlua 0.13 records combat in game (`wowlua prof report`); the design's profiler only shows Studio's sessions and speedscope files. |
| S012 | Studio keeps its own state (settings, keybindings, recent workspaces, layouts keyed by the workspace's path) in the system's folder for application data, never in the workspace **(user, M1)** | Repositories stay clean. |
| S013 | On macOS the window has no title bar of its own: the traffic lights sit at the left of Studio's drawn bar, which holds the design's row; the menu is the system menu bar **(user, M1)** | As Zed and VS Code do on macOS; the design's row stays one row. |
| S014 | The frame budget: building a frame's UI takes at most 4 ms at the 99th percentile, so a 120 Hz display never drops a frame for Studio's own work; the frame statistics check it **(user, M0)** | Performance comes first (S005); a number makes it testable. |
| S015 | The name is written **wowlua studio**, all lowercase, as wowlua is; the short form in running text is Studio, as the design writes it **(user, M0)** | The brand writes its product names in lowercase; the design's prose calls it Studio. |
| S016 | Docking is Studio's own code, not a docking library: four docks (left, main, bottom, right), each a run of groups of tabbed panels (stacked in the side docks, side by side in the main and bottom ones), the panels board's five drop zones, and floating panels as egui viewports (windows of their own natively, embedded windows where a platform has only one) **(user, M1)** | egui_dock and egui_tiles float panels inside the main window only, and their models differ from the design's fixed docks and drop zones; a dock made for the design stays small and cheap to draw. |
| S017 | Each page's layout preset is the panels its artboard draws, where it draws them; the panels board's presets where they differ: the tests page shows the results in the main area, and Claude is a page of its own (conversations, chat, tools) **(user, M1)** | The panels board has presets for five of the twelve pages, and two of them disagree with the pages' artboards. |
| S018 | The command palette's amber prompt holds the mode (`/` files, `>` commands, `#` symbols, `@` this file, `:` a line); the field holds only the text after it. A sign typed into an empty field switches the mode; backspace in an empty field goes back to files **(user, M1)** | The palette artboard shows the sign twice, in the prompt and in the field. |
| S019 | Every command is in one registry with its menu, its palette entry and its keys; a menu shows only the commands that exist, and a menu with none yet is left out until its milestone adds some. On macOS the same registry fills the system menu bar, behind its application menu **(user, M1)** | The design names the menus but not their contents; one list keeps the menus, the palette and the keys from drifting apart. |
| S020 | The app's icon is the design system's mark tile: on macOS inside Apple's icon grid (a rounded square of 824 of 1024 px, the mark at 84 % of it so the corners never cut the brackets), on Windows and Linux the square tile as designed; `scripts/app-icon.py` draws both from the tile's outlines **(user, M1)** | The window showed the system's default icon; a full-bleed square looks out of place in the macOS Dock. |
| S021 | The theme is chosen in the settings only, not in the status bar; until the settings page (M10), from the command palette and the view menu **(user, M1)** | The design's status bar has a dark/light switch; the theme is a setting you change rarely. |
| S022 | `unsafe` is denied in the workspace, not forbidden, and allowed in one file only: `crates/wowlua-studio/src/traffic_lights.rs`, which moves macOS's window buttons onto the centre line of Studio's 40 pt title bar through AppKit (objc2), 13 pt from the left, again whenever AppKit moves them back, not in full screen **(user, M1)** | AppKit centres the buttons in its own 28 pt title bar, so they sat high in Studio's; neither winit nor egui can move them. |
| S023 | The title bar shows the [wl] mark itself at 20 px (the design system's smallest size for it), rasterized from its outlines at the display's pixel size, not the 16 px pixel mark the title bar artboard uses **(user, M1)** | The pixel mark's own proportions (a short w, 1 px strokes) read as a different logo next to the app's icon. |
| S024 | The start page shows only what works: open a folder, a new addon, adopting one, recent workspaces, this computer (wowlua, the WoW installation, Blizzard's UI). The design's GitHub parts (open from GitHub, signing in) come with M12, the Claude row with M14 **(user, M2)** | A page of disabled promises; the page grows when they are built. |
| S025 | One workspace per window: opening another folder asks whether to replace this window's workspace or open a new window; each window has its own layout, session and title **(user, M2)** | As VS Code and Zed do; a debug session, a game screen and a layout belong to one workspace. |
| S026 | The new-addon form's check mode, Git and starter world profile are `wowlua new`'s (`--check`, `--no-git`, `--world-profile`, wowlua decision T476); Studio calls wowlua's library, so the CLI and Studio make the same package **(user, M2)** | `wowlua new` had none of them; Studio doing them on its own would make two kinds of new package. |
| S027 | Studio runs Git through the `git` program. Adopting an addon in a Git repository switches to a new branch `wowlua/adopt` first and commits the adoption there, so it is one commit to review **(user, M2)** | The design adopts on a new branch; the `git` program is what wowlua's own Git steps use, and settles M11's open question. |
| S028 | A WoW installation picked in Studio is kept in `wow.path` of `~/.wowlua/config.json`, which `wowlua install`, `dev` and `prof report` read; Studio finds the installation as they do **(user, M2)** | Studio and the command line always agree on the installation. |
| S029 | The start page shows Blizzard's UI per flavor whose client folder the installation has, from wowlua's cache (`~/.wowlua/cache/blizzard-ui`): there, or not downloaded yet with a download **(user, M2)** | wowlua downloads Blizzard's UI source on first use (T204); the design's "from the installation's client" did not match. |
| S030 | The start page's what's new is the `### New` part of wowlua's changelog for the version built in (`wowlua_driver::release_notes`) **(user, M2)** | It always matches the wowlua inside Studio. |
| S031 | Each window is a process of its own: opening a folder in a new window starts Studio again with that folder; windows share recents and settings through their files **(user, M2)** | A hung session or a crash takes one window down, not all of them. |
| S032 | Opening a folder with no `wowlua.json` offers to adopt it (the adopt form for that folder) **(user, M2)** | A plain Lua AddOn becomes a package by adopting it; nothing else in Studio works without one. |
| S033 | The adopt form's "TOC files only" is `wowlua init --no-pkgmeta` (wowlua decision T477): a `.pkgmeta` is left as it is **(user, M2)** | `wowlua init` converted a `.pkgmeta` whenever it existed; the design offers both. |
| S034 | The new-addon form offers flavors as the design draws them: camelot, with retail and vanilla shown as planned and disabled **(user, M2)** | The emulated client runs camelot only; the form grows with the flavors it can run. |
| S035 | A new addon's folder defaults to the folder holding the most recently opened workspace, else the home folder **(user, M2)** | Addons usually sit side by side in one projects folder. |
| S036 | The new-addon form's name is the folder's name, as `wowlua new <folder>` takes it; `--name` (the AddOn's name) is passed only when the folder was given another name **(user, M2)** | `--name` sets the AddOn's display name: passing the form's `pull-timer` as it would make an AddOn called `pull-timer`. |
| S037 | What's new is titled with the exact version built in (`what's new in 0.13.1`), its `### New` part alone (S030) **(user, M2)** | A patch release's section is not the minor version's; 0.13.0's has 35 entries. |
| S038 | The explorer shows dot files and folders (`.github`, `.pkgmeta`) but `.git` and `.DS_Store`; build output (`dist`, `target`, `node_modules`) stays out of it and the watcher **(user, M2)** | The design's explorer shows `.github`. |
| S039 | The adopt form's folder field has a `choose…` button for the system's folder picker **(user, M2)** | Typing a path is the only way in the design. |
| S040 | The file menu of the start page has new addon and adopt addon; a workspace's window has close folder instead, and settings (a page of the workspace's window) only there **(user, M2)** | The start page has no pages; its forms are the start page's own. |
| S041 | The status bar can show frame stats: the frames drawn in the last second and the last frame's time (building and drawing it, as eframe measures it). A view command turns them on and off, off at first, kept in the settings **(user, M2)** | To watch Studio's speed while using it (S014). Studio draws only on change, so the count is the redraws, 1 a second while idle. |
| S042 | wowlua's language server gains semantic tokens, quick fixes (code actions from the fixes its diagnostics carry) and folding ranges, in a wowlua pull request; Studio uses them as any editor would **(user, M3)** | The server had none of them; adding them in wowlua gives VS Code the same. |
| S043 | The terminal panel is a full terminal emulator: the user's shell in a pseudo-terminal (`portable-pty`, ConPTY on Windows) read by `alacritty_terminal`, drawn by Studio. Desktop only; the browser build has none **(user, M3)** | Interactive programs and colours work as in any terminal; settles the open question. |
| S044 | Background jobs come with M3 (the jobs board): the check is the first job **(user, M3)** | Builds, test runs and installs of later milestones run as jobs too. |
| S045 | Highlighting comes from wowlua's own lexer (`wowlua-syntax`) in Studio's process; the server's semantic tokens are drawn over it when they arrive **(M3)** | The colours follow the grammar the compiler reads, at once, with no grammar file to keep in step. |
| S046 | JSON with schemas is Studio's own: `wowlua.json` and world profiles (`tests/profiles/*.json`) are checked, completed and explained against the schemas wowlua's crates make (`wowlua_manifest::schema_json`, `world::schema_json`) **(M3)** | wowlua's server reads the manifest but serves no JSON editing; VS Code has its JSON service, Studio has none. |
| S047 | Notifications (the notifications board): a toast over the status bar's end for 6 s (longer while pointed at; errors until dismissed), then a tray at the status bar's end with the unread count. The tray keeps this window's notifications until it closes. Files deleted outside, finished jobs, the notes of M2 (adopted, opened in a new window, did not open) and new releases are notifications **(user, M3)** | Things that happen while you look elsewhere need one place; the note over the window covered only M2's. |
| S048 | An open file deleted outside Studio closes, with a notification whose restore writes your last version back and opens it **(user, M3)** | A tab kept open would bring a deleted file back on the next save. |
| S049 | An open file changed outside Studio reloads when it has no unsaved edits; with unsaved edits the editor shows the design's banner: compare (a read-only diff of your text against the disk's), keep mine, take theirs. Saving over a file that changed since Studio read it shows the same banner instead of writing. The banner names a Git checkout as the cause when `.git/HEAD` changed with the file **(user, M3)** | Nothing is overwritten or lost without a choice; the diff is the start of M11's. |
